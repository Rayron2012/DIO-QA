# Níveis de Testes

### Testes de Unidade

Entendo que os testes de unidade são testes ao nível do código. Esses testes são efetuados por unidades, sendo fácil de rastrear quando ocorre uma falha; a unidade pode ser entendida como a menor parte de um programa, como uma função ou métodos.

Normalmente efetuados pelos próprios desenvolvedores, é importante entender que o ideal é criar os testes antes da esteira de desenvolvimento, mas, conhecendo o mercado de trabalho, acredito que muitas vezes os testes são desenvolvidos ou criados após os códigos.

### Testes de Integração

Testes de integração são efetuados depois dos testes unitários. Aqui se testa se todo o sistema está conversando entre si de acordo com o esperado; aqui se testam as integrações do próprio sistema, assim como com outros sistemas.

Normalmente, são considerados como a segunda etapa da pirâmide de testes.

### Testes de Sistema

Aqui é testado tudo como um todo. A ideia é validar se o software, em sua totalidade, atende aos requisitos definidos previamente. Pode ser entendido como a etapa principal dos testes não funcionais, pois se testam carga, segurança, desempenho e usabilidade.

Essa etapa é efetuada após os testes de integração e antes da implantação.

### Testes de Aceitação

São normalmente realizados pelo cliente ou representante final, que valida se o sistema cumpre os critérios de aceitação que foram combinados previamente.

Pode ser considerada a última etapa da pirâmide, pois é efetuada antes da implantação final do software. Percebi que, como é a última etapa, pode ser a mais lenta e a mais suscetível a erros humanos, principalmente dos testadores finais.
